## Immutable original and currentness

Local originals use distinct record kinds in the existing
`ProspectiveResearchStore`, its exclusive transaction and immutable retain
mechanism. The existing research commissioning prerequisite is preserved.
An original binds input, deterministic result, method/parameters, operation
identity, exact hashes and actual capture/completion timestamps. Equivalent
source and methodology reuse the retained original across automatic/manual
invocations and restart. Exact previously validated record bytes reuse a process-local
validation proof, so unchanged operations do not recalculate through the result
decoder. New or changed records receive full validation; restart independently
replays immutable mathematical validation without creating a new assessment.
Known original disappearance is unavailable, never an automatic recapture.
New source or method requires a new original.

A completed validated result is preserved before the final currentness decision.
If source changes, retain the original and a separate stale disposition. Never
rewrite the original to become current. Historical validation failure is reported
as unavailable and preserved; no repair, migration or automatic re-execution is
performed. Store and commissioning errors remain visible. No unretained result
may be represented as a durably retained original.

Current promotion requires the current committed run/publication, successful
admission generation, candidate and exact consumed input to agree again under
the existing owner boundaries. Active successor work and contradictory control
state withhold current display even while the old publication still exists.
Completion and final-proof timestamps must not exceed the current owner clock
at preparation or display. Clock rollback withholds current use without rewriting
or misclassifying a chronologically valid historical original as corrupt.
