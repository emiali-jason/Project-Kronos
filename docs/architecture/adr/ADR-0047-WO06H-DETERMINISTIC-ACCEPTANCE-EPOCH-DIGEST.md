# ADR-0047 — WO-06H deterministic acceptance-epoch capability digest

**Status:** Approved bounded engineering by direct Sponsor / EA order, 12 September 2026. Publication, compatibility-record enrollment and runtime restoration require separate authorization.
**Owner:** Intraday WO-06H epoch compatibility.
**Authority:** Sponsor order 6f1cb6d8-20a8-4b41-804d-0d5d31d10ca2, SHA-256 `7dc4a8b18ffbd1402fadc266197e11021d78423d7b6a321f45767ff6bb448971`.
**Extends:** [ADR-0044](ADR-0044-WO06H-SUCCESSOR-CAPABILITY-BOUNDARY.md). Its strict same-epoch rule remains the default. This decision adds one content-addressed collateral-equivalence transition and does not change successor commissioning.

## Decision

`WO_06H_ACCEPTANCE_EPOCH/1.2.0` replaces the 1.1.0 `marshal.dumps(function.__code__)` implementation digest with `KRONOS-WO06H-ACCEPTANCE-EPOCH-SEMANTIC-AST/1.0.0`. The new SHA-256 input is canonical JSON containing the capability and digest-policy identities, epoch policy, methodology, Narrow CPR publication, document schemas and identity pattern, transition invariants, an explicit ordered callable allowlist represented as canonical Python AST, and the separate complete `WO_06H_LIVE_SHADOW` calculation capability declaration.

The source loader supplies the UTF-8 bytes pinned at process startup. Each named definition is selected from parsed module source. Docstrings and AST position attributes are removed. `ast.dump` retains names, arguments, annotations, decorators, expressions, constants, operators and control flow. Canonical JSON fixes key ordering and representation before hashing. Filename, checkout path, loader origin, line/column positions, code-object metadata, memory addresses, import warmth and interpreter-owned wrapper bytecode cannot affect the digest.

Decorated `EpochStore.transaction` is represented by its owned source definition, including the governed `@contextmanager` declaration and body. The runtime wrapper generated by `contextlib` is excluded. A change to the owned decorator expression or transaction body changes the digest; a different stdlib wrapper implementation does not.

## Exact historical compatibility

Historical 1.1.0 proofs remain immutable. A new `compatibility` document may establish only the exact `WO_06H_ACCEPTANCE_EPOCH/1.1.0` proof to exact `1.2.0` proof transition for one existing epoch. It binds the epoch, acceptance and window identities; complete historical and corrected capability/configuration identities; an immutable `DIGEST_SCOPE_COLLATERAL` diagnosis; the exact protected-module old/new source byte SHA-256 rows; deterministic-equivalence evidence hashes; explicit Sponsor/EA authorization reference; and the existing content-addressed envelope/integrity hash.

Restoration first applies ordinary complete equality. If that fails, the store searches only exact `WO06H-COMPATIBILITY-<sha256>` records whose epoch and two complete proof identities match. Zero matches means incompatible; more than one means ambiguous. The one match must validate all bindings, exact 1.1.0→1.2.0 versions, identical configuration, identical complete capability map except the epoch declaration, identical `WO_06H_LIVE_SHADOW` calculation declaration, the exact protected module set and valid evidence hashes. No revision, digest or epoch is hard-coded. The relation is non-transitive and cannot authorize 1.2.0 semantic drift or another capability mismatch.

The compatibility record creates no acceptance, window, epoch, transition pointer, observation or backfill. Enrollment is an external trusted evidence operation and is not exposed through the runtime HTTP interface. Engineering and publication alone cannot restore production authority.

## Consequences

Equivalent source derives the same capability across processes, checkouts, loaders, filenames, import states, line offsets and wrapper provenance. Policy/schema, calculation declaration, protected control-flow or callable semantics change the digest. Existing epoch restoration can proceed without manufacturing a new acceptance only after the separately authorized exact compatibility record is retained. Corrupt, incomplete, detached, unrelated or future mismatches remain inactive.

WO-11 policy and evidence are outside this digest correction. PAPER Position and Paper Observation remain one lot, use eligible WebSocket `last_price`, retain the inclusive five-second lateness ceiling and the three trading exits, and keep LIVE and post-entry analytical invalidation uncommissioned in V1.
