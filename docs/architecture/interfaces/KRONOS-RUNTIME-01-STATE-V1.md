# RUNTIME-01 shared state and release admission

**Status:** Sponsor/EA authorized engineering candidate, version 1.0.0. See ADR-0050.

GET /runtime/status is read-only and returns schema, policy, policy_checksum, process (PID/revision/source_state), maintenance, rest_authentication, rest_capability, monitoring and owner_restoration. It performs no filesystem scan, Provider request, owner creation or lifecycle write. /status retains historical diagnostic fields and adds runtime_ready. The latter is true only after startup completion; it is not a trading-health or market-freshness assertion.

maintenance contains protocol, state, active, generation, startup and failure. State is INACTIVE, ACTIVE or FAILED_ACTIVE. A non-null old generation is retained provenance, not active maintenance. startup is NOT_ASSESSED, READY or BLOCKED. Failure is a bounded restoration/health reason, never arbitrary exception text. No endpoint accepts caller-supplied READY or source qualification.

Monitoring reports the in-process shared registry. CONNECTING means a session was requested but no connection callback has established its state; CONNECTED means an observed transport callback, not REST authentication. IDLE means no session and no observed connection state. DISCONNECTED remains visible after a previously used transport closes. Owner and subscription counts are registry facts; they are not exchange acknowledgements. Latest observations retain connection ID, timestamps, source sequence and the normalized continuity/ordering/recovered flags. Missing observations remain null. Consumer lifecycle records remain the authority for per-owner gap eligibility; no historical continuity is reconstructed.

Canonical admission failures: CANONICAL_LAUNCHER_REQUIRED, CANONICAL_SIGNATURE_INVALID, SOURCE_NOT_CLEAN, SOURCE_REVISION_NOT_AUTHORIZED, SOURCE_PROOF_UNAVAILABLE. Qualification occurs at transition/startup only. The direct remote lookup is bounded to 20 seconds per command; failures do not trigger a retry or unqualified startup. The existing 45-second handoff age and 30-second replacement readiness ceiling remain strict.

Automatic maintenance completion records RUNTIME_STARTUP_MAINTENANCE_EXIT_V1 with runtime_identity, maintenance_identity, timestamp and VERIFIED_CANONICAL_STARTUP trigger. It cannot create acceptance, epoch, window, compatibility, research or trading authority. Existing manual MAINTENANCE_EXIT_V1 remains historical and unchanged.

The explicit startup_retained_owner_evidence field freezes existing Swing Paper Observation track/monitoring state, reason and last factual timestamp once at composition. retained_owner_scope labels it as a startup snapshot, not a current lifecycle projection. It explains suspended owners even while the hub registry is empty. Subsequent current lifecycle truth remains on the owned track projection; no polling filesystem scan or automatic gap repair is introduced.

Provider projection uses the dedicated inert KRONOS-PROVIDER-RETAINED-STATUS/1.0.0 contract. Existing operational capability getters can synchronize/revoke or acquire leases and are never used by this status surface. ABSENT, RETAINED_UNEXPIRED, EXPIRED, UNAVAILABLE_CLOCK and UNAVAILABLE describe retained capability plus known expiry; they do not establish fresh Provider health. Existing operational admission still revalidates on use. Retained lease count and lifecycle are labelled as retained facts. No Provider session_status, capability.active, lease acquisition/revocation or expiry persistence occurs on reads. A legacy embedded test server without this injected projection reports NOT_EXPOSED rather than calling an operational getter.
